# Política de Segurança

## Reportar uma vulnerabilidade

Não publique detalhes exploráveis de uma vulnerabilidade em uma issue pública.

Use o recurso **Private vulnerability reporting** do GitHub para este repositório, se estiver habilitado. Se não estiver disponível, entre em contato com o dono do projeto, Maicon Wissmann, pelo GitHub e solicite um meio seguro para compartilhar os detalhes. Não publique detalhes exploráveis em issue pública.

Inclua, quando possível:
- versão/commit afetado;
- sistema operacional e condições necessárias;
- passos mínimos para reproduzir;
- impacto observado;
- logs ou prova de conceito sem dados pessoais, credenciais ou segredos reais.

## Prazo e coordenação

O mantenedor confirmará o recebimento assim que possível, investigará o relato e coordenará uma correção e divulgação responsável. Não há SLA formal publicado neste momento.

## Escopo

O escopo inclui o aplicativo TraduSaga, seu código, scripts de build, workflows e artefatos oficiais. Vulnerabilidades em serviços externos ou bibliotecas de terceiros devem ser reportadas aos respectivos mantenedores, sem deixar de informar o impacto no TraduSaga.

## Boas práticas

- Nunca envie senhas, tokens, chaves de API ou certificados em issues/PRs.
- Não desative antivírus, Smart App Control, SmartScreen, UAC ou outros controles do Windows para executar o aplicativo.
- Baixe versões somente de um canal oficial verificável.
